[3] โครงสร้างฐานข้อมูล
----------------------------------------------------------------
Lookup tables:
  category_income, category_expense, payment_type, detail_master

Transaction tables:
  income  : date, year, month, detail_id(FK,nullable), detail_text,
            category_id, amount, note
  expense : เหมือน income + payment_type_id

detail_id เป็น NULL/0 ได้ กรณีผู้ใช้พิมพ์รายการเองโดยไม่เลือกจาก master
schema ปัจจุบันครบแล้ว ไม่ต้อง alter เพิ่ม

หมายเหตุ: ensure_schema() ใน db_manager.py ใช้ CREATE TABLE IF NOT EXISTS
+ ensure_column() สำหรับ detail_text จึงปลอดภัยกับ DB เก่าและ DB ใหม่


[4] การตัดสินใจออกแบบ + เหตุผล  ** อ่านก่อนแก้โค้ด **
----------------------------------------------------------------
4.1 Snapshot detail_text
    เก็บข้อความจริงลงตารางธุรกรรมเลย ไม่ JOIN detail_master ตอนอ่าน
    WHY: ข้อมูลเก่าไม่เปลี่ยนตามการแก้ชื่อใน master
         + ผู้ใช้พิมพ์เองได้โดยไม่ต้องเพิ่มเข้า master ก่อน
    >> อย่าเปลี่ยนไปใช้ JOIN ล้วน

4.2 Portable Clinic Category
    จับคู่หมวด "คลินิก" ด้วยชื่อ String ไม่ใช่ ID
    WHY: ย้ายไฟล์ DB ข้ามเครื่องแล้วยังทำงานถูก แม้ ID ไม่ตรงกัน
    >> อย่า optimize ไปใช้ ID

4.3 Thai Display via WebView
    ใช้ HTML Table แทน monospace text
    WHY: ฟอนต์ไทยบน iOS ความกว้างไม่คงที่ จัดคอลัมน์ด้วย space ไม่ตรง

4.4 PickerPopup auto_close
      - auto_close=False : "รายละเอียด" (detail_master)
        เลือกแล้วเอาไปใส่ช่องค้นหาให้แก้ต่อได้ ไม่ปิด popup ทันที
      - auto_close=True  : "หมวดหมู่" และ "ประเภทการชำระ"
        เลือกแล้วปิดทันที
    >> ทำ picker ใหม่ที่ไหน ให้เลือก auto_close ตามลักษณะข้อมูล

4.5 Table-driven Schema ใน db_manager.py (ยืนยันใน v6)
    ใช้ list TABLES เป็นศูนย์กลางนิยามตาราง (name / title / columns)
    ทุกฟังก์ชัน (insert/update/fetch/form) generate จาก metadata นี้
    WHY: เพิ่มตารางใหม่ทำได้โดยแก้จุดเดียว ไม่ต้องเขียนฟอร์มใหม่
    >> เพิ่มตารางใหม่ = เพิ่ม dict ใน TABLES + เพิ่ม method ใน DataViewer
       + เพิ่ม mapping ใน show_data()

4.6 show_data() ใช้ dict mapping ไปยัง DataViewer
    WARNING: dict viewer_actions ถูกสร้างตอนเรียก show_data()
    ถ้า DataViewer ขาด method ใดใน mapping จะเกิด AttributeError ทันที
    แม้ผู้ใช้ยังไม่ได้เลือกตารางนั้น
    >> เพิ่ม key ใน mapping เมื่อไหร่ ต้องมี method จริงใน data_viewer.py ด้วยเสมอ


[5] ปัญหาที่เคยเจอ + วิธีแก้ (อย่าย้อนรอยเดิม)
----------------------------------------------------------------
- ฟอนต์ไทยจัดคอลัมน์เพี้ยน           -> ใช้ HTML Table
- สระอำ U+0E33 นับความกว้างผิด       -> เพิ่ม exception ให้ width = 1
- AttributeError INPUT_ROUNDED_RECT  -> เข้าถึงผ่าน getattr()
- layout() ถูกเรียกซ้ำ                -> ใช้ _built guard flag
- จอ iPad ขนาดต่างกัน                 -> คำนวณขนาดแบบ dynamic
- AttributeError 'FormX' has no attribute 'end_editing'
                                      -> ใช้ ui.end_editing()
- ScrollView ไม่มี send_subview_to_back
                                      -> add subview ตัวที่ต้องการให้อยู่ล่างสุดก่อน
                                         (ลำดับ add = z-index)
